# Security Standards Baseline

Use current official standards as reference points, then tailor to the application.

## Baselines to consider

- OWASP Top 10 for web application risks
- OWASP API Security Top 10 for API-specific risks
- OWASP Top 10 for LLM Applications for AI-specific risks
- NIST Secure Software Development Framework for SDLC practices
- SLSA for supply-chain integrity and provenance
- SPDX or CycloneDX for software bill of materials
- WCAG 2.2 for accessibility requirements when web content is user-facing
- OpenTelemetry for vendor-neutral telemetry semantics

## Security review structure

1. Assets
2. Actors
3. Trust boundaries
4. Data flows
5. Abuse cases
6. Controls
7. Tests/scans
8. Residual risk
9. Release decision
